# Project research

This directory tracks questions, source decisions, consequential research activity, and gaps that cross article boundaries.

## Source lifecycle

`discovered` → `candidate` → writer decision → `accepted` / `rejected` → optional `superseded`

- **Discovered** material may remain in `inbox/` until it has enough metadata for the catalog.
- **Candidate** means worth evaluating, not trustworthy or relevant by default.
- **Accepted** means the writer approves it for project use; acceptance does not make every claim in it true.
- **Rejected** retains a reason so weak sources are not repeatedly rediscovered.
- **Superseded** preserves provenance when a better edition, standard, dataset, or correction exists.

Article-specific acceptance is recorded in the article's `sources.md`. A source can be accepted project-wide yet irrelevant to a particular article.

## Evidence provenance

For every material fact, definition, quotation, or attributed argument, preserve:

`claim → evidence record → literature note → source catalog entry → original source`

For audiovisual material also preserve creator/channel, upload date, duration, stable URL, caption type, transcript method, timestamp, and whether quoted wording was checked against the recording.

## Research session pattern

1. Name the question before searching.
2. Ask AI to return candidates and originals, not a blended answer.
3. Record promising candidates in the catalog.
4. Let the writer accept or reject them.
5. Take notes only from the source itself.
6. Update evidence and gaps rather than drafting an unsupported answer.
7. Record consequential changes in `research-log.md`.
